# webrtc_client 第一轮 UI 与可执行程序交付

## 交付目标

- 使用 Qt 6 + QML 创建可启动的 `webrtc_client`，本轮仅实现 UI，暂不开发 `webrtc_engine`。
- 交付当前 macOS 环境可直接启动的 `dist/webrtc_client.app`，包含运行所需的 Qt 库和 QML 资源，并提供完整源码。
- 面向 Windows、macOS、Linux 保持跨平台构建能力，提供构建与部署说明；未实际构建的平台明确标注待验证。
- 本轮不包含发行签名、公证和安装器。

## 界面与交互

- 深色专业风格，使用系统标题栏；默认窗口 `1440×900`，最小 `960×640`。
- 上方为固定三行三列的九宫格，卡片等大并随窗口缩放，显示通道编号、“暂无视频”和“未连接”，预留保持 16:9 比例的视频区域。
- 下方工具栏依次包含六个按钮：**启动音视频设备、开启扬声器、预览摄像头、开始推流、开始拉流、设置**。
- “启动音视频设备”合并麦克风与摄像头的入口；扬声器保持独立。按设备、预览、流控制和配置分组，设置靠右。
- 按钮包含本地图标、中文文字、悬停提示和键盘焦点反馈；最小窗口尺寸下全部可见。
- 所有按钮本轮只显示“〈功能名称〉尚未接入，当前仅展示 UI”，不访问设备、不连接网络、不切换业务状态；暂不制作设置表单。

## 工程与部署

- 使用 CMake、C++17、Qt 6.5 及以上版本，依赖 Qt Quick 和 Qt Quick Controls，可执行目标命名为 `webrtc_client`。
- `webrtc_client_ui/` 独立承载启动入口、QML 组件、主题和图标；本轮不创建 engine 实现或业务接口。
- 实施时准备当前缺少的 Qt/CMake 工具链，完成编译并使用 Qt 部署工具收集运行依赖。
- Qt 路径通过 `CMAKE_PREFIX_PATH` 指定，不写死本机路径；交付说明提供准确产物位置和启动方式。
