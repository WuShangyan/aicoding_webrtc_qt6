# webrtc_client 构建与运行

## 当前交付

- `dist/webrtc_client.app`：macOS Apple Silicon 本地运行版，Qt/QML 依赖随应用部署。
- 双击 `.app`，或在项目根目录运行 `open dist/webrtc_client.app`。
- 本轮仅 UI：九宫格与六个工具栏入口，点击只显示占位提示。没有 engine、设备采集、网络连接或设置表单。
- UI 位于 `webrtc_client_ui/`，C++ 仅负责启动。未来 engine 应作为独立模块提供能力，避免 QML 直接依赖 WebRTC。

## 依赖

CMake 3.21+、C++17 编译器、Qt 6.5+ 的 Quick、QuickControls2、Svg 模块；Ninja 可选。Qt SDK 的架构与编译器必须一致。

macOS 可使用 Homebrew：

```sh
brew install cmake ninja qtbase qtdeclarative qtsvg
```

Windows 可安装 Qt 官方 MSVC 64 位 SDK、匹配的 Visual Studio C++ 工具链和 CMake。Linux 可安装发行版提供的 Qt 6.5+ 开发包（包含 Quick Controls、QML 模块及 SVG 插件），或使用 Qt 官方桌面 SDK。

## 配置、编译与部署

以下命令在项目根目录执行，`<Qt安装前缀>` 替换为 Qt SDK 的实际前缀（Homebrew 为 `/opt/homebrew`；官方 SDK 通常为对应版本下的 `macos`、`msvc*_64` 或 `gcc_64` 目录）。

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="<Qt安装前缀>" -DCMAKE_INSTALL_PREFIX=dist
cmake --build build --config Release --parallel
cmake --install build --config Release
```

如使用 Ninja，在配置命令加 `-G Ninja`。Windows 在对应 Visual Studio 开发终端执行。

| 平台 | 部署入口 | 状态 |
|---|---|---|
| macOS | `dist/webrtc_client.app` | 本轮实际构建与运行验收，详见会话文档 |
| Windows | `dist/bin/webrtc_client.exe` | 尚无对应环境，待构建与验证 |
| Linux | `dist/bin/webrtc_client` | 尚无对应环境，待构建与验证 |

CMake 安装阶段使用 Qt 官方 [QML 部署 API](https://doc.qt.io/qt-6.5/qt-generate-deploy-qml-app-script.html) 收集依赖。Windows/macOS 由 Qt 部署工具处理；Linux 的部署能力随 Qt 版本不同，最低支持版本可能仅安装程序，需要目标机安装匹配的 Qt/QML 运行时。本轮没有交付 Linux 独立运行包。

macOS 产物是本机 arm64 构建，不是 Intel/Apple Silicon 通用版本；使用本地临时签名，不含 Developer ID、公证和发行安装器。

## 验收

安装 Qt 的开发环境可执行：

```sh
QT_QUICK_CONTROLS_STYLE=Basic qmltestrunner -input tests
```

PowerShell 设置环境变量使用 `$env:QT_QUICK_CONTROLS_STYLE="Basic"`，然后执行 `qmltestrunner -input tests`。测试检查三种窗口尺寸的布局边界、六个按钮提示、提示自动关闭和键盘激活。需要图形桌面会话。

最终仍需从部署入口启动应用，检查图标、文字、缩放、最大化和退出。构建产物与部署产物在 `build/`、`dist/`，不应作为源码文件提交。
